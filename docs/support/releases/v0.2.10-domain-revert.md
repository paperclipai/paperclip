# Release: v0.2.10 — Domain reverted to voyonder.com, billing fix, signup checkbox consolidation

**Date**: 2026-08-15
**Commit**: `5c6d1e6`
**Type**: Fix release
**Related issues**: VOY-1140, VOY-1035, VOY-975

## Summary

This release reverts the domain migration to voyonder.app, keeps production at voyonder.com, fixes a billing page prerender crash, and consolidates the signup legal checkbox. It also moves the footer to the root layout so legal links appear on all public pages.

## Changes

### 1. Domain revert to voyonder.com (VOY-1140)

The domain migration from voyonder.com → voyonder.app (started in VOY-1023/VOY-1033) is **deferred**. All canonical URLs, OpenGraph tags, Twitter cards, sitemaps, and email addresses have been restored to voyonder.com.

**What this means for support**:
- Customer-facing URLs remain at `voyonder.com` — no change from the user's perspective
- Email addresses: `support@voyonder.com`, `privacy@voyonder.com`
- API/webhook URLs reference `voyonder.com`
- The `.app` domain migration is not cancelled, just deferred. If it resumes, another release note will cover it.

**Troubleshooting notes**:
- Some cached pages or emails may still reference `voyonder.app` until caches expire
- If a customer reports seeing `voyonder.app` in an email or page, it's a stale cache — the source is now `.com`
- Any hardcoded `voyonder.app` URLs in browser bookmarks, shared links, or external integrations will still resolve (the `.app` domain forwards)

### 2. Billing page force-dynamic fix

The `/settings/billing` page was crashing during prerender. Marked as `force-dynamic` to prevent server-side prerendering of the authenticated billing UI.

**What this means for support**:
- If a customer reports a blank billing page or a crash when visiting Settings → Billing, this was the root cause
- The fix ensures the billing page always renders dynamically (not prerendered), so it works with authenticated Stripe data
- No action needed from customers — it's fixed server-side

### 3. Join page checkbox consolidation (VOY-1035)

Removed the duplicate VOY-1017 terms acceptance checkbox. A single controlled checkbox (VOY-1033) now handles terms acceptance on the join page. The submit button is disabled until terms are accepted.

**What this means for support**:
- Customers see one checkbox to accept Terms of Service at signup (was: two checkboxes — one duplicate)
- No change to the legal requirement: terms must still be accepted before account creation
- Analytics event `trackLegalTermsAccepted` fires on acceptance

### 4. Footer moved to root layout (VOY-975)

The Footer component was moved from `app/page.tsx` (homepage only) to `app/layout.tsx` (root layout), so legal links (Documentation, Release Notes, Privacy, Terms, Pricing, Gallery, Contact) now appear on ALL public pages.

**What this means for support**:
- Customers can find legal links from any public page, not just the homepage
- Pages affected: `/privacy`, `/terms`, `/pricing`, `/documentation`, `/documentation/releases`, `/gallery`, `/blog`

### 5. Internal metadata stripped from legal pages

Author, Date, Status, and Product Principle metadata headers were removed from Privacy Policy and Terms of Service pages. These were internal workflow artifacts that should never have been visible to customers.

**What this means for support**:
- If a customer previously reported seeing "Author: CTO" or "Status: Draft" on a legal page, that's fixed
- Legal pages now render cleanly starting from the policy content
- The full expanded Privacy Policy (not the v1 abbreviated version) is restored
