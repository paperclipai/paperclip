# Release: v0.2.13 — Stripe tier sync hardening, stale ref auto-repair, OAuth redirect fix

**Date**: 2026-08-16
**Commit**: 02d2992 (branch `fix/voy-944-must-fix-items`, merged to main)
**Type**: Bugfix + hardening release
**Related issues**: VOY-944, VOY-905, VOY-896
**QA verified**: VOY-1231

## Summary

This release hardens Stripe subscription tier synchronization, prevents stale customer reference errors, and fixes a Google OAuth redirect mismatch. These are robustness fixes — no new user-facing features — but they materially affect billing behavior for users whose Stripe subscription state has drifted from what Voyonder's database shows.

## Changes

### 1. Stripe tier sync hardening (VOY-905 + VOY-944)

**What changed in `syncTierFromStripe()`:**

- **Active/trialing subscription check** — The function now checks specifically for `active` or `trialing` subscriptions when determining a user's tier. Previously it accepted any subscription status, which could map expired, past_due, or unpaid subscriptions as active and keep a user on a paid tier they were no longer entitled to.

- **Deleted customer detection** — Stripe returns `{deleted: true}` on customer objects that have been deleted in the Stripe dashboard. The sync function now detects this flag and handles it gracefully instead of crashing with a stale reference error.

- **Auto-downgrade to free** — When no active or trialing subscription exists, the user is automatically downgraded to the `free` tier. This repairs cases where a webhook was missed (e.g., during an outage) and the user remained on a paid tier after their subscription expired or was cancelled.

- **Safe status mapping (`mapStripeStatus()`)** — A new typed function replaces unsafe direct type casts for mapping Stripe subscription status values to Voyonder's internal tier model. This prevents runtime type errors from unexpected or malformed Stripe status values.

**What this means for support:**

- A user who cancelled their Stripe subscription will now correctly see their tier downgrade to `free`. Previously they might have remained on the paid tier until a manual sync was triggered.
- If a customer says "I cancelled but I'm still on the Elite tier", that state may self-correct on the next sync. If it doesn't, a manual tier check may be needed.
- Users whose Stripe customer was deleted on the Stripe side (e.g., during account cleanup) will no longer crash the sync process — they'll be safely downgraded to free.

### 2. Stale reference auto-repair (VOY-896)

**What changed in `findOrCreateStripeCustomer()`:**

- When the function encounters a database record pointing to a Stripe customer ID that has been deleted in Stripe, it automatically removes the stale DB record and creates a fresh Stripe customer.
- Prevents "No such customer" errors during checkout and subscription operations.

**What this means for support:**

- Users who previously encountered "No such customer" errors when trying to upgrade or manage billing should now succeed without manual database cleanup.
- If a customer reports "I can't upgrade my account" or "I get an error when trying to change my plan", this fix may resolve it. If not, escalate for manual Stripe customer re-link.

### 3. OAuth redirect fix (NEXTAUTH_URL)

**What changed:**

- Google OAuth callback now uses `NEXTAUTH_URL` for all redirects, fixing a proxy-host mismatch that could occur when Voyonder is behind a reverse proxy or load balancer.

**What this means for support:**

- Users who experienced Google login redirecting to the wrong host (e.g., internal server name instead of voyonder.com) should now correctly redirect to voyonder.com.
- If a customer reports "Google login takes me to the wrong page" or "Google login doesn't work behind a proxy", this fix addresses it.

## Behavioral Changes Support Should Know

| Before v0.2.13 | After v0.2.13 |
|---|---|
| `syncTierFromStripe()` accepted any subscription status as active | Only `active` or `trialing` subscriptions count as active |
| Deleted Stripe customer caused sync to crash/error | Deleted customer detected and handled gracefully |
| Users with expired/cancelled subs could remain on paid tier indefinitely | No active sub → auto-downgrade to `free` on next sync |
| Stripe status used unsafe type casts | `mapStripeStatus()` provides safe typed mapping |
| Stale Stripe customer refs caused "No such customer" errors | Stale refs auto-repaired by creating fresh Stripe customer |
| Google OAuth redirect could resolve to proxy hostname | All OAuth redirects use `NEXTAUTH_URL` |

## Support Escalation Path

| Issue | Severity | Action |
|---|---|---|
| User on wrong tier after cancellation | Medium | Ask user to verify in Stripe; if tier not self-correcting within 24h, run manual sync or escalate |
| "No such customer" error persists | High | Check if Stripe customer exists; if DB ref is stale, auto-repair should handle it on next operation; if not, escalate to CTO |
| Google OAuth redirects to wrong URL | High | Verify NEXTAUTH_URL env var is set correctly on the server; if the app is behind a proxy, check proxy headers config |
| Billing page crash | High | Check if force-dynamic is set on billing route (v0.2.10 fix); if new crash, escalate to CTO |
| User reports incorrect tier | Medium | Check Stripe dashboard for actual subscription state; if Stripe says active and Voyonder says free, run `syncTierFromStripe` manually or ask user to trigger a sync via billing page |
