## Overview

v0.5.0 Phase 1 is a security-hardening and stability release that fixes trust-boundary issues discovered during the v0.4.0 review process, adds the Marketplace agent-hiring flow, and improves the onboarding experience. It also brings the Company Templates feature to production stability.

---

## What's New

### Marketplace Agent Hiring

Hire pre-built agents from the Paperclip Marketplace. The new `POST /companies/:companyId/marketplace/agents/:ref/hire` endpoint lets you deploy ready-made agent configurations (skills, instructions, tools) with one API call. Marketplace hires are gated behind:

- **`agents:create` permission** — only users/agents with agent-creation grants can hire marketplace agents
- **Board approval** — if the company requires board approval for new agents, marketplace hires go through the same approval flow as manually created agents

Agent marketplace listings include adapter type, capabilities summary, and starter skills. The hired agent is created as a full company agent with all standard lifecycle capabilities.

### Onboarding Improvements

The onboarding flow has been updated with asset packs for seven new organizational roles:

- **Troop Master** — Scout troop management configuration
- **Trail Master** — Outdoor activity coordination
- **Outdoor Activity Chair** — Event and activity planning
- **Onboarding Chair** — Member onboarding workflows
- **Fundraising Chair** — Fundraising campaign management
- **Treasurer** — Financial tracking and reporting
- **Chaplain** — Member support and communications
- **Advisor** — General guidance and mentorship
- **Ranger** — Operational support
- **Troop Committee Chair** — Committee oversight
- **Quickstart** — Immediate productivity setup

Each role comes with default skills, knowledge packs, and a starter issue tailored to the role's domain.

### Company Templates (Production-Stable)

Company Templates graduated from the v0.4.0-alpha preview to production-ready. One-click deploy pre-built companies:

- **Travel Concierge** — Trip planning and customer support
- **Support Ops** — Customer support ticket management
- **Engineering Team** — Software development lifecycle
- **CPA Firm** — Accounting and tax preparation

Each template comes with pre-configured agents, skills, knowledge-base articles, and a starter issue. The `GET /companies/:companyId/templates` endpoint lists available templates, and `POST /companies/:companyId/templates/:ref/deploy` instantiates the full company in a single call.

## Security Hardening (VOY-1367 Fixes)

### B1 — Billing Trust Boundary

**Problem**: Billing mutation routes (subscription create/change, usage records, invoice sync) only checked company membership, not board-user context. An agent with matching companyId could cancel subscriptions or create charges.

**Fix**: All billing mutation routes now require `requireBoardUser` — agents are explicitly excluded. Board-user context is verified before any Stripe API calls or subscription mutations. A test suite confirms agent API keys receive HTTP 403 on billing mutations.

### B2 — Memory Index Restoration

**Problem**: Migration 0137 (`0137_last_betty_ross.sql`) dropped the `memory_records_embedding_hnsw_idx` HNSW vector index, the `created_at` index, and the `company_binding` index without recreating them. The memory adapter still runs `embedding <=> CAST($1 AS vector)` cosine search, which degraded to sequential scans.

**Fix**: Migration 0141 (`0141_restore_memory_indexes.sql`) recreates the HNSW vector index (cosine distance, 16 dimensions), the `created_at` B-tree index, and the composite `(company_id, created_at)` binding index on `memory_records`. The schema definition in `packages/db/src/schema/memory.ts` is also updated to declare these indexes explicitly so future migrations preserve them.

### B3 — Notification Idempotency

**Problem**: `notifyExecutionErrorOnce` used an in-memory Set keyed on a string-encoded composite key, which (a) didn't survive process restart and (b) didn't prevent duplicates from concurrent sends. The same execution error could generate duplicate notifications across node restarts or under concurrent delivery.

**Fix**: Replaced in-memory dedup with a database-backed idempotency mechanism using `metadataJson->>'runId'` as the dedup key. The dedup uses a partial unique index (migration 0142) filtered to execution-error notifications. If a duplicate notification is attempted, the unique constraint violation is caught and silently suppressed.

### S1-S4 — Should-Fix Items

| Item | Fix |
|---|---|
| **S1**: `getEffectiveChannels` silently dropped unknown channel types from fixed enum | Switched from destructuring to explicit iteration; unknown channels are logged and skipped |
| **S2**: `sendDigest` produced markdown-wrapped plain text instead of raw text | Digest email body now outputs plain text without wrapping |
| **S3**: `DEFAULT_NOTIFICATION_PREFERENCES` declared in two places with different values | Consolidated to a single authoritative declaration in `notification-types.ts` |
| **S4**: Company member check used ambiguous `member` variable that could shadow parent scope | Refactored to explicit `companyMember` scoping |

### P0-A: Marketplace Hire Authorization

**Problem**: The marketplace hire route skipped the `agents:create` permission check and the board-approval gate, allowing any active non-viewer member to create an agent with arbitrary `command` via user-supplied `adapterType`/`adapterConfig`.

**Fix**: Added `assertCanCreateAgentsForCompany` (checking `agents:create` grant) and the `requireBoardApprovalForNewAgents` gate to the marketplace hire route, matching the standard `POST /companies/:companyId/agents` route.

### P0-B: db-health-watchdog External Mode Exit

**Problem**: `installDbHealthWatchdog` in external mode called `process.exit(0)` on signal, contradicting the module's own documented design (which says external mode should exit cleanly without side effects).

**Fix**: Changed to `process.exit(0)` → warn-only in external mode. The watchdog now logs a warning and returns gracefully instead of terminating the host process.

## Known Issues

- Marketplace agent listings are currently curated by the Paperclip team. Self-publishing to the marketplace is not yet available.
- Company Templates deploy all agents as `hermes_gateway` type. Local adapter templates are not yet supported.
- The memory HNSW index rebuild (migration 0141) may take several minutes on large memory_record tables. Run during maintenance windows.
- Notification digest scheduling currently supports daily and weekly intervals. Custom cron schedules are not yet available.
- Stripe webhook handling is idempotent but does not retry failed webhook deliveries automatically — manual re-sync via the billing dashboard is required if a webhook is missed.
