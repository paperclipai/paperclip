# Release: v0.2.13 — Stripe billing robustness fixes (VOY-944/VOY-896)

**Date**: 2026-08-15
**Tag**: `83a1cee`
**Merge**: `6ee4e82`
**Type**: Fix release
**Related issues**: VOY-944, VOY-896, VOY-905, VOY-1218

## Summary

This release hardens Voyonder's Stripe billing integration with five targeted fixes: deleted-customer detection, safe subscription status mapping, automatic downgrade-to-free on cancellation, stale-customer reference repair, and trialing subscription sync. These are the items identified during the VOY-944 must-fix audit and VOY-896 stale-ref investigation.

## Changes

### 1. Deleted Stripe customer detection (VOY-944)

`validateStripeCustomerExists()` now checks the `{deleted: true}` flag that Stripe returns for deleted customers, not just a 404 response. When a Stripe customer record is soft-deleted on Stripe's side, this is now correctly detected instead of treated as a valid customer.

**What this means for support**:
- Previously, a deleted Stripe customer reference could silently pass validation (no 404 was returned — Stripe returns `{deleted: true, id: "cus_..."}` with a 200 status). This fix catches that case.
- If a customer reports unexpected subscription behavior and has a cancelled/deleted Stripe account, this fix ensures the system handles it correctly going forward.
- No action needed from customers — it's fixed server-side.

### 2. Safe subscription status mapping (VOY-944)

`mapStripeStatus()` is now used instead of unsafe `as unknown as SubscriptionStatus` TypeScript casts. Subscription status is now mapped through a proper Prisma enum, eliminating the risk of runtime errors from unexpected Stripe status values.

**What this means for support**:
- Eliminates a class of potential "Internal Server Error" responses from billing endpoints when Stripe returns an unexpected status value.
- If a customer was seeing billing page errors related to subscription status, this was likely the cause.
- No action needed from customers.

### 3. Downgrade-to-free on full cancellation (VOY-944)

Users who cancel their subscription now have their tier auto-downgraded to **Free** on next login, even if the Stripe cancellation webhook was lost or delayed. Previously, cancelling via Stripe but losing the webhook could leave a user with a "paid" tier status despite no active subscription — a stuck paid tier.

**What this means for support**:
- This is the most impactful customer-facing fix. Users who cancelled but remained on a paid tier will now correctly revert to Free on their next login.
- If a customer contacts support saying "I cancelled but I'm still being charged" — this fix prevents that scenario going forward. For existing stuck users, the next login will resolve it.
- No manual intervention needed from support for new cancellations. For historical stuck cases, ask the customer to log out and log back in.

### 4. Stale-customer auto-repair (VOY-896)

Stale Stripe customer references (where the Stripe customer ID in the database points to a deleted or invalid customer) are now auto-repaired during checkout and billing portal visits. `syncTierFromStripe()` validates customer references before syncing, and repairs them automatically when stale references are encountered.

**What this means for support**:
- Previously, a user with a stale Stripe customer reference in their account could get stuck at checkout or on the billing page. The system now self-heals on these visits.
- VOY-896 is fully subsumed — no separate fix needed.
- If a customer reports "I can't update my billing info" or "checkout fails" — this fix may resolve it on the next attempt.

### 5. Trialing subscription sync — active||trialing filter (VOY-905)

`syncTierFromStripe()` now lists all non-canceled subscriptions and filters to `active || trialing` status only. Previously, the sync could pick up expired or incomplete subscriptions, potentially assigning incorrect tier levels.

**What this means for support**:
- Users on trial subscriptions are correctly synced as trialing (not downgraded or misclassified).
- Users whose subscription has expired are no longer incorrectly assigned an active paid tier.
- No customer action needed — this is a sync correctness fix.

## Support Escalation Path

| Issue | Severity | Action |
|---|---|---|
| User cancelled but still sees paid tier | Medium | Ask them to log out and log back in — downgrade-to-free triggers on next login |
| User can't access billing/checkout | Medium | Stale-customer auto-repair runs on billing page visit — try again; if still broken, escalate to CTO |
| Billing page shows unexpected subscription status | Medium | Safe status mapping fix applies server-side — check if user has an unusual Stripe subscription status |
| User reports incorrect tier (trial vs paid vs free) | Low | Trialing sync fix applies — verify their Stripe subscription status and tier assignment |
