## Actions Taken

### 1. Critical Incident Response: Server Boot Crash

**Detection**: The launchd-managed server was in a crash loop with `SyntaxError: @paperclipai/shared does not provide export 'DEFAULT_NOTIFICATION_PREFERENCES'` followed by `TransformError: Multiple exports with the same name 'notificationPreferences'`.

**Root cause**: The v0.5.0 notifications feature (VOY-1342) was partially wired in. `heartbeat.ts` (staged change) imports `notificationService` from `notifications.ts`, which imports `DEFAULT_NOTIFICATION_PREFERENCES` from `@paperclipai/shared`. But:
- `packages/shared/src/index.ts` did not re-export the notifications types module
- `packages/db/src/schema/index.ts` had duplicate export blocks for the same table names (from `notification_preferences.js` and `notifications.js`)

**Fixes applied**:
- Added `NOTIFICATION_TYPES`, `NOTIFICATION_CHANNELS`, `DIGEST_FREQUENCIES`, `DEFAULT_NOTIFICATION_PREFERENCES` + all notification types to `packages/shared/src/index.ts` (re-exported from `./types/notifications.js`)
- Consolidated `packages/db/src/schema/index.ts` to a single export block from `./notifications.js`
- Deleted the duplicate `notification_preferences.ts` file

**Verified**: Server is up and healthy (`/api/health → 200 OK`).

**Remaining blockers** (VOY-1363, for Founding Engineer):
- `server/src/services/knowledge-starter-packs.ts` source file missing
- `stripe` and `web-push` npm deps not in server/package.json
