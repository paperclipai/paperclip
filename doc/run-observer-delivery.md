# Run observer delivery (experimental)

A trusted service can receive short-lived, status-only credentials for a specific agent run. This delivery is disabled by default. It does not give the receiver an agent token or a signing key.

Configure all three server environment variables together: `PAPERCLIP_OBSERVER_SINK_SOCKET` (an absolute Unix socket path), `PAPERCLIP_OBSERVER_SINK_COMPANY_ID`, and `PAPERCLIP_OBSERVER_SINK_AGENT_ID`. The socket and its immediate directory must belong to the Paperclip server user and must not grant access to group or other users. The path must use a real directory, not a symlink. The sink must not inherit the server signing key or board credentials in its environment. The server and sink user are one trusted operating-system security domain. This is not isolation from other processes running as that user. The sandboxed worker must not have the socket, its directory, or host process access. The execution adapter and worker isolation must also prevent inheritance or synchronization of the server signing secret and any other host credentials; this delivery does not enforce that boundary.

At runtime the server checks the active run and delivers one newline-delimited JSON object containing `runId` and `token`. The sink replies `ok` followed by a newline. The token can read only the matching observer-status endpoint. Delivery is bound to the configured company and agent. The shared work scheduler renews it only while the execution is active; shutdown and terminal status cancel the deadline. The sink must associate a token with the server-supplied run and must not accept a run selection from an untrusted worker as authority. It must check the matching status endpoint before starting work and continue checking while work is active.

If the initial delivery fails, runtime startup fails closed for the configured agent. If refresh or status checks fail later, the sink must stop or withhold its own work; a token expires in at most 120 seconds and the status endpoint rejects it as soon as a recorded stop is observed. The delivery loop alone cannot stop an external process or prove that an already-admitted network call did not reach its provider. The receiver needs an independent deadline and durable recovery after a host or server failure.

This interface is experimental. Do not send tokens to logs. Do not mount the socket into worker environments. The integration needs independent security review and recovery tests before production use.
