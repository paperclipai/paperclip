# Dark approval unlink participant checkpoint

The canonical `issueApprovalService.unlink` has an optional dark `lifecycleFence` boundary. It captures the company before starting an owned transaction and delegates to `unlinkIssueApprovalInTransaction`. The supplied participant captures all routing scalars, awaits the existing company lifecycle fence before reads, then executes shared canonical issue/approval validation and the scoped link DELETE on that executor. The default omitted/false path retains its non-owning behavior and two-ID DELETE predicate. A missing company is rejected before effects. Neither entry decides an approval or restores an issue.

No production caller opts in. Bulk links, approval decisions and interactions remain nonparticipants. This does not establish common serialization or authenticated authority. Existing restoration is still unwired. Queue admission/revalidation, orphan expiry and the live fifteen-minute bound remain unimplemented.
