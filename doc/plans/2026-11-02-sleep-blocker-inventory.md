## Operator diagnostic

Hold hosting admission and acquire an owned idle drain using the existing [hosting protocol](../idle-sleep-safety.md). An instance administrator or signed Cloud control caller can make one explicit request:

```text
GET /api/instance/task-drain?idleSleepSafety=1&idleSleepDiagnostics=1&ownerId=<current-owner>
```

The ordinary response remains unchanged unless diagnostics are requested. A diagnostic adds `idleSleepSafety.diagnostics: { version: 1, complete, checks: [{ reason, state }] }`. Only fixed reason identifiers and states leave the inspector; it does not return company/plugin/row identifiers, values, counts, paths, SQL, credentials, or errors. Company members and agents cannot read this instance-wide report. Negotiated `scheduledWake=1/2` remains exclusive to verified Cloud control; managed checkpoint authority retains its existing restriction.

States are `none`, `present`, `unknown`, and `not_checked`. `complete` covers applicable **read inspections** under the same current owned hold and generation. It is not a stop certificate. An unperformed backup checkpoint is explicitly `not_checked` even if all read inspection completed. Diagnostics never initiate backups to discover their outcome or force plugin RPCs past unsafe lifecycle fences. No unknown or skipped result can authorize safety `none`.

The opt-in DB SELECT evaluates every existing predicate as a named boolean column, instead of the normal OR short circuit. It runs once in the existing read-only repeatable-read transaction with a five-second statement timeout. It can cost more than an ordinary report and can reconnect/wake the DB. Do not poll it or use it during a suspension observation window. Ownership loss, expired/changed hold, concurrent tracked work, malformed results/configuration, missing migrations, timeout, or unreadable local state remains unknown/incomplete. A failed PostgreSQL statement aborts that snapshot; no later out-of-transaction scan fabricates completeness. Already observed reasons are historical observations of this invalidated request, not current clearance.

## Schedules and local reasons

`routines.schedule` and `issues.schedule` reuse the existing [routine reader](../../server/src/services/idle-scheduled-work.ts) and [issue reader](../../server/src/services/idle-issue-schedule.ts) in the same snapshot when Cloud negotiates the respective capability. Due, malformed, unsupported, foreign-company, overflow, claimed or inconsistent schedules block. Definitions are never advanced/cleared during inspection. An earliest in-process timer is not an external alarm receipt. Routine and monitor proofs still require Cloud to persist the exact alarm and revalidate the owned generation before stop. Agent timers, watchdogs, plugin jobs, merge-confirmation checks, refresh duties, and other unqualified deadlines retain blockers.

The issue reader can accept backlog, unassigned todo, explicit blocked/human-owned waits, untouched onboarding and exact response-driven waits. Live execution, conversations, ready dependency repair and unsupported review/recovery remain conservative. Healthy idle conversation semantics in product documentation do not themselves relax this reader's current `conversation_agent_id` fence; domain owners must reconcile that gap with proof.

[Local inspection](../../server/src/services/idle-local-work.ts) has these fixed reasons:

| Reason | Owning truth, producer, trigger and negative fixture | Remedy / dependency |
| --- | --- | --- |
| `local.startup` | `markIdleStartupComplete` in server startup; unknown until reconstruction completes. | Finish startup/recovery; readiness alone is insufficient. |
| `local.ingress_tracking` | HTTP/upgrade tracking installation; unknown before admission is installed. | Install existing admission adapter before accepting routes. |
| `local.automatic_backups` | Automatic-backup configuration; present unless the report has the existing checkpoint hook. | Backups package qualifies checkpoint/startup backup plus restore; keep backups enabled. |
| `local.tracked_work` | `task-admission.ts` active promise/token count and generation; token starts before work and ends only at settlement. | Let accepted request/scheduler/cleanup/write work settle; unknown writes retain holds. |
| `local.registered_probes` | Aggregate of six production registration owners listed below; present/unknown until each owner's obligation settles. | Owner recovery/resource proof; no generic timer exemption. |
| `local.accounting_spool` | `usage-receipts.ts`; any entry, including malformed/temp/write probe, blocks. | Durable accounting handoff and cleanup; empty/absent valid directory is clear. |
| `local.orphan_spool` | `sandbox-orphan-cleanup-spool.ts`; buffered or filesystem cleanup debt remains work. | Durable cleanup handoff and verified empty spool. |
| `local.registered_spools` | Additional configured spool directories registered by the same owners. | Every directory must be empty/absent; a malformed path/read failure is unknown. |
| `local.quota_recovery` | Company-grouped encrypted credential recovery journals; empty valid company directories are passive. Files, nested/invalid entries or bad roots block/unknown. | Existing quota recovery owns decryption/handoff; diagnostics never read file content or follow symlinks. |

Registered-probe owners are `retained-ai-credential-cleanup.ts` (retained retire/cleanup), `local-ai-login.ts` (browser/deferred retirements), `native-runtime/native-session-executor.ts` (warm/closing sessions and checkpoint saves), `run-evidence-migration-work.ts` (unknown/incomplete/blocked S3 conversion), `provider-trace-retention-work.ts` (unknown discovery or **any future retention deadline**), and `index.ts` terminal workspace recovery (incomplete/failed startup pages). Future provider-trace retention is currently a local blocker; routine/monitor alarms do not cover it. Optional skill-package migration/retention is a distinct path which can wait for next ingress; do not conflate the two.

`plugins.runtime_drain` reports the owning worker manager's existing aggregate proof. Startup locks, worker replacement/crash, missing SDK capability, live RPC/host/PTY/duplex routes, bad response or changed hold remain present/unknown. The collector never exposes the exempted worker IDs. Unsafe inspection is `not_checked`; it is never forced merely to complete diagnostics.

`backup.checkpoint` is an action result, not read coverage. Diagnostic calls leave it `not_checked` and do not create dumps. Ordinary safety reads still run the existing fresh tracked dump/archive-verification/fsync protocol only after all other checks pass, require unchanged generation and retain the restart backup marker. Failed/slow/untracked/concurrent dump work does not authorize sleep. Storage persistence and real restoration belong to backup qualification.

`inspection.hold`, `inspection.generation`, `durable.snapshot` and `local.inspection` describe observation integrity. They cannot convert unresolved work into a clear result. A malformed query result or inaccessible scope produces unknown, never an empty reason list presented as complete.

They retain row identities and due times. [Existing safety regressions](../../server/src/__tests__/idle-sleep-safety.test.ts) continue to exercise consumed retries, coalesced wakes, cleanup/login proof, question handoffs, credentials, plugins, cross-company links and schedule generations.

For a coordinator-provisioned disposable database, set `PAPERCLIP_IDLE_SLEEP_DIAGNOSTICS_TEST_DATABASE_URL` and `PAPERCLIP_IDLE_SLEEP_SAFETY_TEST_DATABASE_URL` to the explicit dedicated `*_test` URL and the existing `PAPERCLIP_TEST_POSTGRES_ADMIN_URL` safeguard. Run suites sequentially with one worker and bounded pools; close clients before coordinator cleanup. Normal CI retains the existing embedded fixture fallback. No diagnostic suite provisions or drops a DB when its explicit URL is set.

The diagnostic does not mutate domain state, establish new external wake coverage, delete retained history, or claim a fleet rollout. History, incoming work, deadlines, backups, and assembled deployed acceptance remain separately owned follow-ups. Every proposed eligibility improvement must supply its exact domain completion and first-producer/reactivation evidence before the predicate changes.
