# Paperclip v2026.1009.0

> Released: 2026-10-09

Paperclip v2026.1009.0 carries 130 commits, promoted from `2026.1006.0-beta.0`. The headline is that outside assistants can now join your team: Claude Code, Codex, OpenCode, and any MCP client can connect to Paperclip as a signed-in person, review work, and delegate tasks, all behind an experimental setting. Around that: Chat leads the navigation with each agent's tasks and artifacts beside the conversation, the Connections catalog pulls in accounts you already linked in Composio and Arcade, connections carry usage instructions that reach your agents automatically, Claude Sonnet 5.5 and GPT-6.1 Sol arrive with refreshed harnesses, and agents can safely update company skills. Underneath, Codex runs survive server restarts and model-capacity errors, workspace restore locks move to crash-safe SQLite file locks, and default agent instructions shrink to a fraction of their former size.

## Breaking Changes

- **Workspace restore locks change protocol; stop every old process before upgrading.** Restore and agent-file collection locks are now OS-backed SQLite file locks under `<instance root>/locks/directory-merge/`, released by the kernel when a process crashes. Old and new versions must not write to the same instance root at once: drain and stop all old server and worker processes (including other hosts or containers) before upgrading or rolling back, then move any leftover legacy `<hash>.lock/` directories to a scratch location. Never delete or move the new `.lock.sqlite` files. See `doc/workspace-restore-locks.md`. ([#14869](https://github.com/paperclipai/paperclip/pull/14869))
- **Stored tool grants are enforced as written.** A grant whose `scope.allow` list does not match a tool, connection, or application no longer falls through to a broader policy; grants with unknown selectors or malformed restrictions now deny access. Review custom grants after upgrading if an agent loses a tool it previously used. ([#14915](https://github.com/paperclipai/paperclip/pull/14915))

## Highlights

- **Assistants join your team over MCP** — A new "Assistant Connection (MCP)" card in Connections lets Claude Code, Codex, OpenCode, and generic MCP clients connect to Paperclip through browser OAuth or device-code consent and act as the signed-in user: read and search tasks, create and delegate work, leave human comments, read documents and deliverables, and follow results through signed event webhooks ([#14846](https://github.com/paperclipai/paperclip/pull/14846)). Consent shows the client and organization, write access can be opted out, requests can be pinned to one company, and a `paperclip mcp` CLI device login bridges local stdio clients; it is off by default behind Settings → Experimental → "Assistant connections (MCP)" and requires an HTTPS `PAPERCLIP_PUBLIC_URL` ([#14933](https://github.com/paperclipai/paperclip/pull/14933)).
- **Chat leads the way** — With Agent Chat enabled, Chat is the first row in the Work navigation, the chat rail lists every eligible agent, and the side panel shows that agent's recent tasks and artifacts; a new experimental "Combined Inbox + Task List" setting folds Inbox into Tasks as views ([#15100](https://github.com/paperclipai/paperclip/pull/15100)). The Chat entry reopens the last conversation you visited ([#14848](https://github.com/paperclipai/paperclip/pull/14848)), and the chat header shows the agent's avatar ([#14726](https://github.com/paperclipai/paperclip/pull/14726)).
- **One catalog for every account** — The Connections Apps catalog discovers accounts already connected upstream in Composio, Arcade, and supported Executor gateways and groups them with native accounts under one app card, with source chips, search, and pagination ([#15254](https://github.com/paperclipai/paperclip/pull/15254)). AgentMail is a default connection with inline setup cards in Agent Chat ([#14772](https://github.com/paperclipai/paperclip/pull/14772)), Neon joins the catalog with OAuth or API-key sign-in ([#14980](https://github.com/paperclipai/paperclip/pull/14980)), Asana works again with a default "Sign in with Asana" ([#14756](https://github.com/paperclipai/paperclip/pull/14756)), and AI accounts gain a "Check usage" action that reads current provider limits for Codex, Claude, Grok, and OpenRouter ([#14936](https://github.com/paperclipai/paperclip/pull/14936)).
- **Connections carry instructions for agents** — A connection can hold editable usage instructions that are delivered to every authorized agent turn across the native runner, legacy adapters, and HTTP/process contracts. Honcho, Mem0, Zep, Supermemory, and Cognee ship defaults, the editor appears in setup and the Permissions panel, and agent Instructions show a read-only "From connections" section ([#15216](https://github.com/paperclipai/paperclip/pull/15216)).
- **New models, refreshed harnesses** — Claude Sonnet 5.5 is selectable for Claude Code agents with Low through Max effort, and the qualified Claude runtime moves to Claude Code 2.1.286 ([#14993](https://github.com/paperclipai/paperclip/pull/14993)); GPT-6.1 Sol joins the Codex adapter with Fast mode and Ultra effort, Bedrock gains Sonnet 5.5, and the shared pins move to Codex 0.160.0 and OpenCode 1.18.34 ([#14942](https://github.com/paperclipai/paperclip/pull/14942)). Claude and Codex model menus now list models in the same order as the Claude and ChatGPT apps ([#14917](https://github.com/paperclipai/paperclip/pull/14917), [#14918](https://github.com/paperclipai/paperclip/pull/14918)).
- **Agents maintain company skills** — Native-runner agents get an `update_skill` tool that rewrites a company skill with version checking and safe retries, recorded in version history and the audit log; the skill file API gains optional `expectedVersionId` and `idempotencyKey` fields ([#15049](https://github.com/paperclipai/paperclip/pull/15049)). Newly created agents receive a default set of configuration grants so they can finish agent, tool, skill, and task setup without manual permission work ([#15283](https://github.com/paperclipai/paperclip/pull/15283)).
- **Codex runs that survive restarts and capacity limits** — A native Codex turn killed by a server restart resumes in the same conversation once the old process is proven gone ([#15297](https://github.com/paperclipai/paperclip/pull/15297)); a model at capacity shows a "Model at capacity" card and retries automatically after one and then two minutes ([#15347](https://github.com/paperclipai/paperclip/pull/15347)); a model the ChatGPT account cannot use shows "Model unavailable" with guidance instead of generic recovery ([#15299](https://github.com/paperclipai/paperclip/pull/15299), [#15304](https://github.com/paperclipai/paperclip/pull/15304)); and Codex keeps its stock base prompt, receiving Paperclip's context as additive developer instructions ([#14920](https://github.com/paperclipai/paperclip/pull/14920)).
- **A rebuilt New task dialog** — The dialog is built on the shared task composer with a Project and Worktrees bar, remembered assignee, project, and effort, and task mentions in suggestions; the status, reviewer, approver, and watchdog controls move out of the dialog into task properties, and new tasks default to the last assignee used ([#15091](https://github.com/paperclipai/paperclip/pull/15091)). Tasks created without a title get a clean plain-text provisional title ([#15047](https://github.com/paperclipai/paperclip/pull/15047)).
- **Far shorter default instructions** — New companies and hires get role descriptions instead of procedural manuals: the default CEO instructions drop from roughly 1,900 words to 20 ([#14985](https://github.com/paperclipai/paperclip/pull/14985)), new non-CEO hires receive a one-sentence default manual ([#14948](https://github.com/paperclipai/paperclip/pull/14948)), and the bundled planning skills shrink to about 400 words combined and no longer force a child-task matrix ([#15296](https://github.com/paperclipai/paperclip/pull/15296)). Existing saved manuals and custom bundles are unchanged.

tasks stopped during native preparation on an older build regain Retry and accept new messages ([#15020](https://github.com/paperclipai/paperclip/pull/15020), [#15022](https://github.com/paperclipai/paperclip/pull/15022)); `write_document` and other semantic tool calls no longer fail when a document merely discusses credentials ([#14937](https://github.com/paperclipai/paperclip/pull/14937)) or contains credential-looking text ([#15301](https://github.com/paperclipai/paperclip/pull/15301)); - **Chat and task UI** — Steer and Interrupt show your message immediately and deliver to the active run even after a model or effort change, and a stopped native startup offers Retry ([#15015](https://github.com/paperclipai/paperclip/pull/15015)); ## Upgrade Guide

- **Migrations `0294`–`0305`** run on upgrade: `0294` adds a `tool_mcp_gateway_tokens` expiry index; `0295` and `0296` add aggregator account snapshot and sync tables; `0297` adds `resource_lifecycle_events` and `0300` rewrites its action check constraint; `0298` adds `tool_connections.agent_instructions` and backfills default instructions for existing Honcho, Mem0, Zep, Supermemory, and Cognee connections; `0299` adds AI connection pool, router cursor, and task pin tables plus `company_secrets.ai_session_epoch`; `0301`–`0305` add the public MCP OAuth client, grant, token, receipt, event subscription, device-flow, and admission tables. All are additive; `0298` is the only one that updates existing rows.
- **Stop all old processes before upgrading** ([#14869](https://github.com/paperclipai/paperclip/pull/14869)): the new SQLite restore-lock protocol cannot coexist with the old directory locks. Drain every server and worker that writes to the instance root, move leftover legacy `<hash>.lock/` directories out of `<instance root>/locks/directory-merge/`, then start the new version. The same applies to rollback.
- **Review custom tool grants** ([#14915](https://github.com/paperclipai/paperclip/pull/14915)): grants with unknown scope selectors or malformed restrictions now deny instead of falling through.
- **New experimental settings**, all off by default: "Assistant connections (MCP)" (`enablePublicMcp`) exposes the public MCP endpoint and requires `PAPERCLIP_PUBLIC_URL` to be an HTTPS origin ([#14933](https://github.com/paperclipai/paperclip/pull/14933)); "Combined Inbox + Task List" (`enableCombinedInboxTasks`) folds Inbox into Tasks ([#15100](https://github.com/paperclipai/paperclip/pull/15100)); `enableAiConnectionRouters` turns on connection pools and has no UI toggle ([#14967](https://github.com/paperclipai/paperclip/pull/14967)).
- **Connection instructions for custom adapters** ([#15216](https://github.com/paperclipai/paperclip/pull/15216)): process adapters receive `PAPERCLIP_CONNECTION_INSTRUCTIONS_FILE`, the path to a private JSON file with the connection instructions for the run (empty when there are none); HTTP adapters receive the same text as `connectionInstructions` in the request body. Built-in harnesses need no change.
- **Harness pins moved** to Codex 0.160.0, Claude Agent SDK 0.3.286 (Claude Code 2.1.286), and OpenCode 1.18.34 ([#14942](https://github.com/paperclipai/paperclip/pull/14942), [#14993](https://github.com/paperclipai/paperclip/pull/14993)). Custom sandbox images built with Claude Code older than 2.1.284 must be rebuilt before Sonnet 5.5 works on the CLI path, and the controller and runner should be deployed before promoting a sandbox image with the new pins; remote Codex now accepts 0.149.0 up to but excluding 0.161.0.
- **New defaults**: newly created standard agents receive default configuration grants, while existing agents are unchanged ([#15283](https://github.com/paperclipai/paperclip/pull/15283)); the runner's `--listen-port` still defaults to 43127 ([#15353](https://github.com/paperclipai/paperclip/pull/15353)); silent active runs are flagged after 5 and 15 minutes instead of 1 and 4 hours, with no automatic cancellation ([#14979](https://github.com/paperclipai/paperclip/pull/14979)).
- No other configuration or API changes require action.
