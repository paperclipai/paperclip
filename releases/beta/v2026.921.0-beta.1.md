# Paperclip v2026.924.0

> Released: 2026-09-24

Paperclip v2026.924.0 carries 77 commits, promoted from `2026.921.0-beta.1`. The headline is reliability: a deep hardening pass over the native runner and chat recovery — approval and Stop races, session continuity, sandbox reconnection and cleanup — alongside a friendlier face: agent personas throughout the app, an animated onboarding character, and a rebuilt Slack setup. Around those: agents can review GitHub pull requests as scheduled review bots, Railway joins the connector catalog with governed deployment tools, approvals and answers queue during active runs instead of bouncing, and execution harnesses now default to full auto.

## Breaking Changes

- **The legacy Composio broker is retired.** The API-key catalog method, broker clients, session creation, account synchronization, child lifecycle and toolkit routes, and the Services tab are all removed. Existing legacy Composio connections stop working, and there is no automated migration — the experimental MCP aggregator connectors (below) are the successor path; see the Upgrade Guide for the manual steps. Vercel provenance is untouched. ([#13758](https://github.com/paperclipai/paperclip/pull/13758))
- **Execution harnesses now default to full auto.** Native runs default Claude/ACPX to `approve-all`, OpenCode to `allow`, and Codex to approval-and-sandbox bypass, and the legacy adapters follow the same policy — provider tools and connected tools included. Explicitly configured restrictive modes are preserved, and Paperclip's own approval decisions still enforce controller authority; only the *defaults* change. Operators who relied on unconfigured agents inheriting restrictive provider gates should set an explicit mode. ([#13686](https://github.com/paperclipai/paperclip/pull/13686), [#13693](https://github.com/paperclipai/paperclip/pull/13693))

## Highlights

- **Agents get faces** — Static persona images replace agent icons across lists, the sidebar, org charts, tasks, comments, selectors, activity, and dashboards, with one animated pointer-following character in the agent header (reduced-motion and touch fallbacks included) and persona reveal built into agent creation ([#13171](https://github.com/paperclipai/paperclip/pull/13171)). Onboarding opens with the ClipLab sleepy-to-wake hero: the character dozes in gray through setup and wakes in full palette on Review ([#13629](https://github.com/paperclipai/paperclip/pull/13629)). Slack setup can download the agent's avatar as a PNG for the bot identity, from both setup and settings ([#13740](https://github.com/paperclipai/paperclip/pull/13740)).
- **Agents review your pull requests** — A guided setup turns a Paperclip agent into a GitHub review bot: a copyable Claude/Codex prompt walks through App installation, review scheduling, and optional required checks, with the instance origin baked in ([#13717](https://github.com/paperclipai/paperclip/pull/13717)). The GitHub MCP connection also gains the Actions toolset — workflow discovery and dispatch — for existing and new connections ([#13553](https://github.com/paperclipai/paperclip/pull/13553)).
- **Approvals and answers queue during active runs** — Responding to a question or approval while the agent is mid-run no longer bounces: resolved cards project into the run queue as immutable responses, an explicit click steers a response into a compatible native turn (or interrupts for a fresh session), and typed context survives interruption and cleanup ([#13539](https://github.com/paperclipai/paperclip/pull/13539)).
- **Slack setup, rebuilt** — Onboarding splits into six clickable steps with a generated creation link and read-only manifest, credential validation, live account-link status, and a mention-based message test ([#13638](https://github.com/paperclipai/paperclip/pull/13638)). Companies can attach communication guidance to a Slack connection that follows conversations into tasks without per-turn reminders ([#13760](https://github.com/paperclipai/paperclip/pull/13760)), and callback health reports correctly behind Cloud proxies ([#13694](https://github.com/paperclipai/paperclip/pull/13694)).
- **The connector catalog grows** — Railway arrives with OAuth setup and governed deployment tools: service and deployment status, bounded logs, and redeploy/restart/rollback, with workspace-verified access ([#13415](https://github.com/paperclipai/paperclip/pull/13415)). Experimental MCP aggregators (Zapier, Arcade, Composio Connect, Executor) land behind the default-off `enableMcpAggregators` flag, reusing the existing vault, grants, and policy models ([#13755](https://github.com/paperclipai/paperclip/pull/13755)). You.com search joins the self-serve catalog with sign-in, API-key, and keyless free tiers ([#13555](https://github.com/paperclipai/paperclip/pull/13555)), and a CreateOS sandbox provider plugin implements the full environment lifecycle against the CreateOS HTTP API ([#13434](https://github.com/paperclipai/paperclip/pull/13434)).
- **Routines get safe webhooks** — A production trigger wizard adds schedule and webhook choices, one-time credentials, test delivery receipts, and reversible removal ([#13637](https://github.com/paperclipai/paperclip/pull/13637)), and a warning banner flags webhook URLs that may not be publicly reachable — localhost, private networks, HTTP, and Tailscale Serve vs Funnel ([#13684](https://github.com/paperclipai/paperclip/pull/13684)).
- **Skills from work, and for onboarding** — A runner tool turns a completed task's learnings into a company skill, validated and governed by the existing skill policy ([#13538](https://github.com/paperclipai/paperclip/pull/13538)); the first onboarding task runs through a dedicated skill invoked natively on Claude and Codex ([#13517](https://github.com/paperclipai/paperclip/pull/13517)); and an eval guide plus skill-authoring skills join the docs ([#13535](https://github.com/paperclipai/paperclip/pull/13535)).
- **Plugins load image catalogs** — Catalog identities, confined paths, package versions, and bundle hashes are validated before importing code; image selection applies to persisted installs with removal and rollback; and persistent application overlays mount in both UI shells ([#13646](https://github.com/paperclipai/paperclip/pull/13646)).

## Fixes

- **Task conversation and UI** — The chat composer no longer starts out disabled on desktop while the pause-status check is pending (shipped early as stable [2026.916.1](https://github.com/paperclipai/paperclip/releases/tag/v2026.916.1); [#13562](https://github.com/paperclipai/paperclip/pull/13562)). Selecting a single-choice option answers the question without auto-advancing the page ([#13602](https://github.com/paperclipai/paperclip/pull/13602)), every copy button now confirms only after the clipboard write succeeds ([#13603](https://github.com/paperclipai/paperclip/pull/13603)), task history stays visible while retries wait to start ([#13597](https://github.com/paperclipai/paperclip/pull/13597)), the latest failed attempt is retryable even when later automatic retries were cancelled ([#13765](https://github.com/paperclipai/paperclip/pull/13765)), and the connections sign-in screen stops adding a phantom step ([#13601](https://github.com/paperclipai/paperclip/pull/13601)).
- **Runner and native execution reliability** — A broad hardening pass across the native runner: approval and Stop races settle correctly during cleanup ([#13750](https://github.com/paperclipai/paperclip/pull/13750)), a pending startup is awaited before a Stop is acknowledged so a late handle can't submit a provider turn ([#13741](https://github.com/paperclipai/paperclip/pull/13741)), provider sessions persist across turns with question and approval continuations completing on the same run ([#13655](https://github.com/paperclipai/paperclip/pull/13655)), task replies and warm process continuity survive deduplication and helper-thread noise ([#13738](https://github.com/paperclipai/paperclip/pull/13738)), and Agent Chat recovery keeps wake-comment identity and rejects stale retries ([#13678](https://github.com/paperclipai/paperclip/pull/13678)). Sandbox operations got sturdier too: Daytona sessions reconnect after a controller restart with PID-reuse-proof adoption checks ([#13691](https://github.com/paperclipai/paperclip/pull/13691)), termination keeps progressing after bridge loss with fenced cleanup attempts ([#13287](https://github.com/paperclipai/paperclip/pull/13287)), leases stranded active by a restart are swept ([#13515](https://github.com/paperclipai/paperclip/pull/13515)), inherited environments are validated and stale sandbox binaries replaced ([#13677](https://github.com/paperclipai/paperclip/pull/13677)), catalog runtime and grading boundaries are repaired ([#13676](https://github.com/paperclipai/paperclip/pull/13676)), completion-tool rejections name the missing fields ([#13682](https://github.com/paperclipai/paperclip/pull/13682)), and native review handoffs complete with server-validated assignment facts and narrowly scoped reviewer tools ([#13581](https://github.com/paperclipai/paperclip/pull/13581)). Also: plugin workers reach issue-tree resume ([#13757](https://github.com/paperclipai/paperclip/pull/13757)), projects without workspace configuration honor the operator's isolation default ([#13636](https://github.com/paperclipai/paperclip/pull/13636)), managed Git launchers work in sandbox projects ([#13588](https://github.com/paperclipai/paperclip/pull/13588)), an empty `GROK_HOME` no longer masks the host login for local Grok runs ([#13570](https://github.com/paperclipai/paperclip/pull/13570)), and Claude ACP quota classification and reset times survive to the adapter boundary ([#13651](https://github.com/paperclipai/paperclip/pull/13651)).
- **Connection and notification recovery** — Authentication and browser connection failures recover: `CONNECT_TIMEOUT` joins the retry policy, WebSocket constructor failures are handled, and visible queries poll every 15 seconds while the company socket is down ([#13724](https://github.com/paperclipai/paperclip/pull/13724)). Finalized run failures stop re-notifying on every reconnect ([#13739](https://github.com/paperclipai/paperclip/pull/13739)), and chat latency drops while managed session reuse is preserved ([#13710](https://github.com/paperclipai/paperclip/pull/13710)).
- **Server correctness** — PostgreSQL recovers after a transaction connection closes instead of wedging queued queries ([#13643](https://github.com/paperclipai/paperclip/pull/13643)), malformed JSON requests get a constant safe 400 instead of echoing submitted bytes into errors and crash reports ([#13660](https://github.com/paperclipai/paperclip/pull/13660)), heartbeat run IDs are validated before database lookups ([#13657](https://github.com/paperclipai/paperclip/pull/13657)), agent-chat views skip task-only connector reads ([#13654](https://github.com/paperclipai/paperclip/pull/13654)), a caught-up log reader gets an empty read instead of a past-EOF range error ([#13592](https://github.com/paperclipai/paperclip/pull/13592)), and Sentry errors attribute to the loaded source release on both server and browser ([#13719](https://github.com/paperclipai/paperclip/pull/13719)).
- **Cloud-instance URL correctness** — Task links handed to external chats are exact public URLs ([#13699](https://github.com/paperclipai/paperclip/pull/13699)), and chat setup, Telegram registration, and GitHub webhook recovery all use the claimed Cloud origin, with self-hosted configuration precedence preserved ([#13680](https://github.com/paperclipai/paperclip/pull/13680)).
- **CLI and local logins** — The onboarding wizard accepts prompt defaults instead of rejecting the empty input they display ([#13520](https://github.com/paperclipai/paperclip/pull/13520)), and a macOS isolated Claude login is read from its suffixed Keychain item when the credentials file is missing ([#13519](https://github.com/paperclipai/paperclip/pull/13519)).

## Upgrade Guide

- **Migrations `0280`–`0283`** run on upgrade (agent personas, routine webhooks, Slack communication guidance, GitHub review bots).
- **Legacy Composio connections are removed, with no automated migration** ([#13758](https://github.com/paperclipai/paperclip/pull/13758)). Enabling the experimental `enableMcpAggregators` flag only exposes the replacement Composio Connect catalog entry — it does not carry over existing credentials, grants, or access rules. To keep Composio-backed integrations: enable the flag, create and authorize a new Composio Connect MCP connection, re-select its access rules, and remove each retired legacy connection record. Until that is done, agents lose access to the retired tools.
- **Execution defaults changed to full auto** ([#13686](https://github.com/paperclipai/paperclip/pull/13686), [#13693](https://github.com/paperclipai/paperclip/pull/13693)): set an explicit restrictive mode on agents that must keep provider-side approval gates.
- No other configuration or API changes require action.
