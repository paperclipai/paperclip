# Paperclip v2026.802.0

> Released: 2026-08-02

## Breaking Changes

- **Experimental Cloud Sync has been retired** — The flag-gated host-to-host Cloud Upstream flow, its `/api/upstream-sync/*` and `/api/cloud-upstreams/*` routes, the `paperclipai cloud connect|push` commands, and the `enableCloudSync` setting are removed. Migration `0196` drops the experimental connection and run-history tables. Move companies with **Settings → Export / Import** or `paperclipai company export <company-id>` and `paperclipai company import <bundle-path>`. Core company data is not removed; only the unused experimental Cloud Sync connection and run history is discarded. ([#10507](https://github.com/paperclipai/paperclip/pull/10507))

## Highlights

- **Managed installation, updates, rollback, and services** — Paperclip now has a durable per-user install flow with `paperclipai install`, `update`/`upgrade`, `uninstall`, and `service` commands. Managed updates create a database backup, stage and verify a complete side-by-side payload, switch the stable shim atomically, restart the service when needed, and retain previous payloads for rollback. Linux and WSL2 use a systemd user service when available; macOS uses a LaunchAgent. ([#10045](https://github.com/paperclipai/paperclip/pull/10045))
- **Full-fidelity company Import/Export** — Portable bundles now carry labels, blockers, issue documents, work products, monitor state, and content-addressed attachments with SHA-256 verification before writes. Large imports run as resumable jobs, use batched inserts, reject duplicate or incomplete submissions, and accept compressed ZIP uploads so real companies can move between local and hosted instances without a direct network link. ([#10507](https://github.com/paperclipai/paperclip/pull/10507), [#10523](https://github.com/paperclipai/paperclip/pull/10523), [#10531](https://github.com/paperclipai/paperclip/pull/10531), [#10538](https://github.com/paperclipai/paperclip/pull/10538))
- **First-class Decisions** — Agents can propose typed options without applying the underlying mutation immediately. Operators get target-freshness checks, bounded and audited effects, bundles, expiration, terminal outcomes, and a focused attention-feed review flow for cross-issue or destructive choices. Decision cards also use a simpler task-aligned visual model. ([#10010](https://github.com/paperclipai/paperclip/pull/10010), [#10474](https://github.com/paperclipai/paperclip/pull/10474), @tonio-alucema)
- **Agent action audit views** — A new company Audit page and per-agent Audit tab expose permission-gated, redacted action history with filters, links back to tasks and runs, cursor pagination, and a capped CSV export that records its own audit event and protects spreadsheet cells from formula injection. ([#9744](https://github.com/paperclipai/paperclip/pull/9744))

## Improvements

- **Multi-project remote runs** — Paperclip resolves authorized projects mentioned by a task, stages each project into an isolated sandbox directory, reports sync warnings, and enables the multi-project sync path by default. This lets one agent work across related repositories without mixing their worktrees or credentials. ([#10380](https://github.com/paperclipai/paperclip/pull/10380), [#10448](https://github.com/paperclipai/paperclip/pull/10448), [#10469](https://github.com/paperclipai/paperclip/pull/10469), [#10473](https://github.com/paperclipai/paperclip/pull/10473), [#10564](https://github.com/paperclipai/paperclip/pull/10564), @nickyleach)
- **Faster and more constrained sandboxes** — Native file-sync hooks, task-scoped egress grants, reusable ACP sessions, provider-side upload commands, sandbox-handle caching, startup timing, and the Daytona advisory `bwrap` wrapper reduce startup round trips while making file and network intent more explicit. ([#10053](https://github.com/paperclipai/paperclip/pull/10053), [#10070](https://github.com/paperclipai/paperclip/pull/10070), [#10073](https://github.com/paperclipai/paperclip/pull/10073), [#10089](https://github.com/paperclipai/paperclip/pull/10089), [#10155](https://github.com/paperclipai/paperclip/pull/10155), [#10204](https://github.com/paperclipai/paperclip/pull/10204), [#10334](https://github.com/paperclipai/paperclip/pull/10334), [#10335](https://github.com/paperclipai/paperclip/pull/10335), [#10340](https://github.com/paperclipai/paperclip/pull/10340), [#10347](https://github.com/paperclipai/paperclip/pull/10347), [#10352](https://github.com/paperclipai/paperclip/pull/10352), [#10354](https://github.com/paperclipai/paperclip/pull/10354), [#10541](https://github.com/paperclipai/paperclip/pull/10541), [#10554](https://github.com/paperclipai/paperclip/pull/10554), @nickyleach)
- **External secret rotation and clearer secret references** — Supported providers such as AWS Secrets Manager can receive a new value directly from Paperclip while preserving the external reference and audit trail. Secret detail sheets now have shareable deep links, and cross-company environment references are named clearly instead of being shown as missing. ([#10196](https://github.com/paperclipai/paperclip/pull/10196), [#10577](https://github.com/paperclipai/paperclip/pull/10577))
- **Activity-gated routines** — Scheduled routines can skip a tick when no relevant activity has occurred since the prior run. Operators can configure company or project scope in the routine editor, and skipped rows now explain why the routine did not run. ([#9438](https://github.com/paperclipai/paperclip/pull/9438), [#10225](https://github.com/paperclipai/paperclip/pull/10225))
- **Per-user document stars** — Board users can star documents and filter the artifact view to their own starred documents through company-scoped, idempotent membership records. ([#9952](https://github.com/paperclipai/paperclip/pull/9952))
- **Authoritative issue update receipts** — Issue `PATCH` responses now identify the committed fields and blocker changes. Agent clients can also request `Prefer: return=minimal`, which removes the extra confirmation read without changing the default response shape. ([#10478](https://github.com/paperclipai/paperclip/pull/10478))
- **More accurate run costs** — Adapters can report cache-adjusted billed cost separately from nominal cost, and the heartbeat ledger uses it when available. Cache-heavy runs no longer appear over-priced or unpriced in operator cost data. ([#10349](https://github.com/paperclipai/paperclip/pull/10349))
- **Current model discovery** — Static and source-derived model metadata now recognizes Claude Opus 5, Claude Sonnet 5, and GPT-5.6. The Gemini adapter also exports quota-exhaustion detection for plugin reuse. ([#10327](https://github.com/paperclipai/paperclip/pull/10327), [#10280](https://github.com/paperclipai/paperclip/pull/10280), @nguyenm7, [#9780](https://github.com/paperclipai/paperclip/pull/9780), [#3416](https://github.com/paperclipai/paperclip/pull/3416), @but-noah)
- **Better skill operations** — The core Paperclip skill supports beta releases and explicit version selection, managed skills can be renamed safely, inbox gardening uses a confirmation-based archive workflow, and the optional Simplified English skill is available from the catalog. ([#10228](https://github.com/paperclipai/paperclip/pull/10228), [#9688](https://github.com/paperclipai/paperclip/pull/9688), [#10462](https://github.com/paperclipai/paperclip/pull/10462), [#10410](https://github.com/paperclipai/paperclip/pull/10410))

These features remain off by default and can be enabled in **Instance Settings → Experimental**.

A single setup message can drive both the query and summary, and issues referenced by a summary automatically join the watched set. - **Bounded reviews and safer delegation** — Agent-to-agent review loops now escalate to the responsible human after a configurable round limit. Agent assignment refuses paused assignees, delegation refuses cycles back to an open ancestor's creator, and the UI warns when an escalation path ends at a paused manager. ([#10650](https://github.com/paperclipai/paperclip/pull/10650), [#10648](https://github.com/paperclipai/paperclip/pull/10648), [#10658](https://github.com/paperclipai/paperclip/pull/10658), [#10657](https://github.com/paperclipai/paperclip/pull/10657))

## Upgrade Guide

- For a first managed installation, run `npx --registry https://registry.npmjs.org paperclipai install`, then complete `paperclipai onboard`. Existing managed or global npm installations can run `paperclipai update`; `paperclipai upgrade` is an alias. Managed updates back up the database, verify the new payload, and keep the prior payload for `paperclipai update --rollback`.
- Automated onboarding does not install a background service unless you explicitly pass `paperclipai onboard --yes --install-service`. Use `paperclipai service status`, `start`, `stop`, `restart`, and `logs` to manage an existing service.
- Database migrations `0184` through `0197` run automatically on startup. They add status cards, document stars, skill releases, built-in-agent reconciliation, task-watchdog state, and Decisions. Migration `0195` keeps the oldest active built-in agent for each company and marker, terminates newer duplicates, revokes their API keys, and cancels their pending or revision-requested hire approvals. Migration `0196` intentionally removes only the experimental Cloud Sync connection and run-history tables.
- If you used the experimental Cloud Sync commands or routes, export the source company before upgrading and import the bundle at the destination. Import/Export is now the supported transfer and backup path. Version 5 and older bundles remain importable; newer version 6 bundles preserve the additional company state listed above.
- A payload rollback does not reverse database migrations. Keep the managed-update backup, or create your own backup before updating a source checkout or using `--no-backup`.
