## Thinking Path

> - Paperclip is the open source app people use to manage AI agents for work
> - Instance federation (#1084) needs a transport layer first: instances must talk to each other with verifiable identity, per-company permission, and durable delivery that survives crashes and offline peers
> - No such transport exists today. Instances cannot exchange signed, permissioned, crash-durable messages
> - This layer must be correct before any higher-level federation design (discovery, identity federation, company mapping) builds on it
> - This pull request adds a native, opt-in PubSub: Ed25519 instance identities, signed canonical-JSON envelopes with replay protection, per-company trust and subscription ACLs, durable inbox/outbox/history, crash-durable CEO wake, and activity-journal task events
> - The benefit is a reversible transport that lets two or more instances exchange signed messages without changing single-instance behavior

## Linked Issues or Issue Description

Refs paperclipai/paperclip#1084 — this PR lands the transport layer that issue tracks. It is a stepping stone, not the full federation.

## Motivation

Instance federation (#1084) needs a transport layer before anything else: instances must be able to talk to each other with verifiable identity, per-company permission, and durable delivery that survives crashes and offline peers. This PR lands that transport as a native, opt-in feature:

- **Verifiable identity.** Each instance holds one Ed25519 keypair in a mode-`0600` private file plus a public metadata sibling; only the public half is ever exposed or transmitted.
- **Signed, replay-resistant envelopes.** Canonical JSON, Ed25519 signatures, a ±5-minute timestamp window, per-sender nonce retention, and stable-ID/content conflict detection.
- **Least-privilege messaging.** Per-company trust grants, explicit subscriptions, board/CEO-only publishing, CEO-only P2P topics, and read-only observer agents.
- **Durability.** Transactional inbox/outbox/history, redelivery on database row-lock leases (crash-released, no expiry-only gap), crash-durable CEO wake scoped to a standing coordination issue, and `fleet.task.*` events emitted from the committed activity journal rather than live notifications.

This is explicitly a **stepping stone** toward #1084: it advances the federation goal by providing the piece that must be correct before any higher-level federation design — the signed transport and its ACL — while adding no instance discovery, no cross-instance identity federation, and no company-mapping service.

## What Changed

- New feature flag `PAPERCLIP_PUBSUB_ENABLED`. With it unset, no PubSub route is mounted, no worker runs, and nothing is written. No existing route behavior is changed.
- Instance identity: one Ed25519 keypair per instance in a mode-`0600` file with a public metadata sibling; CLI onboarding creates it when the flag is set.
- New routes under `/api/pubsub/*`: identity, trust grants, subscriptions, observers, publish, inbox, ack, history, and the signature-only cross-instance `deliver` endpoint. Board-facing routes are registered in the OpenAPI document; `deliver` is an explicit coverage exclusion (signature-authenticated, not credential-authenticated).
- New shared protocol module (`packages/shared/src/pubsub.ts`): bounded topic/envelope schemas, canonical JSON, sign/verify helpers, topic matching, admission/retention/cooldown constants.
- New Drizzle schema (`packages/db/src/schema/pubsub.ts`) and additive migrations `0294_cloudy_leopardon.sql` + `0295_cultured_inertia.sql` (7 tables, company-scoped nonce keying; journal/snapshot updated, no older snapshots pruned).
- New server services: `pubsub.ts`, `pubsub-crypto.ts`, `pubsub-identity.ts`, `pubsub-wake.ts`, `pubsub-activity.ts`, plus app startup/shutdown wiring.
- CEO wake hardening: per-company coalescing under a company-scoped advisory lock. The in-flight clause tracks the linked run's demonstrated liveness (held while the run still shows liveness evidence — an unexpired controller lease, recent provider output, or a recent start inside the stale window; a SIGKILL orphan that stopped producing evidence releases the slot once the receipt ages out) and the recently-settled clause enforces a post-settlement cooldown — so concurrent server instances cannot both enqueue, a healthy long-running wake is never bypassed by a second message, a crashed owner cannot hold the wake slot indefinitely, and sustained CEO execution is bounded to one run per company per window. Budget-pause cancellations redeliver per message (a message holding any delivered receipt or any operator-stop receipt is never re-armed, and re-arm preserves an in-flight retry backoff); operat…
- Ingress admission hardening: per-peer rate (30/min), per-company wake queue (8), pending-inbox count (200) / byte (4 MiB) quotas checked before durable insert; the byte bound counts the incoming payload; an idempotent retry of a stored message resolves **before** the quotas, so a full quota cannot turn a lost-response retry into `429`; bounded retention (7 d nonces, 30 d acked history) that never sweeps a message whose mandatory wake is still pending.
- Delivery retry classification: transient failures (peer offline, connection refused, timeout, `5xx`, `429` backpressure) retry **indefinitely**, so a peer outage of any length keeps its queued messages and redelivers on return; permanent failures (peer HTTP `4xx` other than `429`, and egress-guard rejections) retry until the row's attempt counter reaches `PUBSUB_DELIVERY_MAX_ATTEMPTS` (40), after which the next permanent failure cancels the row (the message stays in history for operator re-publish).
- Peer-URL egress guard (SSRF): board-managed peer delivery URLs are validated against the repo's remote-HTTP egress guard at trust-write **and** on every dispatch — the host and its resolved address must be public (loopback/RFC1918/CGNAT/other private-reserved rejected) unless the exact host is allowlisted via `PAPERCLIP_PUBSUB_ALLOWED_PRIVATE_HOSTS`; link-local is denied in every mode, and the guard dials the approved address directly so a rebinding DNS answer cannot steer delivery.
- Accepted (non-duplicate) cross-instance deliveries are written to the company activity journal (`pubsub.delivery_accepted`) in the same transaction as the message insert, giving accepted deliveries an inspectable audit trail.
- Prompt containment: the `## PubSub Message` wake section quarantines peer payloads as untrusted data under the repo's source-trust pattern (regression-tested against instruction-shaped payloads).
- Docs (`docs/api/pubsub.md`, `docs/specs/native-pubsub.md`, environment-variable reference, docs navigation) and per-package changelog entries.

## Risks

- **Migration safety:** both migrations are additive (new tables only; `0295` re-keys the nonce table, new in this branch, before it ships anywhere). Journal/snapshot updated per repo convention; no older snapshots pruned. Rollback is safe: revert the code, tables remain unused.
- **Behavioral shift:** none when the flag is unset (routes/workers absent). When enabled, PubSub wakes for a company with an in-flight (liveness-demonstrating) or recently-settled wake are deferred with durable backpressure — messages are never dropped, but delivery-to-wake latency can add up to one cooldown window (60 s) per burst. A wake whose run goes quiet past the stale window (orphan, recovery-parked ownership hold, or an unusually silent live turn) releases the slot after 60 s; wakes admitted while the CEO is actually busy are absorbed by the heartbeat's own admission (per-agent concurrency policy and durable deferral), so the guard relaxation cannot fork parallel CEO runs.
- **Trust boundary:** a granted peer is bounded by the ingress admission quotas (30 messages/min/peer, 8 pending wakes/company, 200/4 MiB inbox) and by the per-agent concurrency policy; a compromised trusted peer is a bounded, rate-limited source, not an unbounded one. The `deliver` endpoint is signature-authenticated (no credential rate limit): invalid traffic is rejected after one trust lookup and one Ed25519 verify, writes no durable state, and consumes no admission quota; a per-source limiter on that route is a documented follow-up, matching the repo's existing webhook endpoints. The CEO wake prompt treats peer payloads as untrusted data (quarantined, regression-tested).
- **Scope:** live acceptance is loopback-only (two instances on one host, real PG, real HTTP, SIGKILL steps). Multi-network deployment is not exercised by this PR.

## Relationship to #1084

This PR **advances** #1084 by landing the signed, ACL'd, crash-durable transport that every later federation layer builds on. It does **not** implement full federation: no discovery, no cross-instance identity or company mapping, and no changes to single-instance behavior. Issue #1084 remains open.

## Rollback

Fully reversible: unset `PAPERCLIP_PUBSUB_ENABLED` (routes/workers absent, data retained but untouched) or revert this branch; the migrations are additive, so reverting the code without dropping the new tables is safe for other workloads.
