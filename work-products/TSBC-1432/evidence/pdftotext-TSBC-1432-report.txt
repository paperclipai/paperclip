Hypothesis
The benchmark harness can keep the existing repetition enforcement and publication gates
while making the ledger auditable: every completed run should write per-pass evidence with
requested/served model identity, timestamps, pass/fail, and failure reasons; aggregate rows
should remain queryable but become derivable from pass rows; historical rows should be
migrated with explicit unknown markers rather than guessed values.

Method
I treated the reopened comment as a rescope: reps were already enforced, so the
implementation target became ledger recording and migration.
Implementation changes:
Added pass start/finish timestamps and served-model verification fields to
benchmark/bench.py run records.

Added AGY same-run self-report probing in benchmark/adapters.py ; pin/self-report
mismatch returns failureReason: served_model_mismatch before task execution.
Updated benchmark/scoring.py so served-model mismatches are never scored.
Expanded benchmark/ledger.py with model_eval_pass rows, aggregate derivation
from pass rows, passes query support, idempotent expanded-schema backfill,
failure-reason classification, and low-success suppression preservation.
Updated benchmark/README.md , benchmark/TSBC-CHARTER.md , and canonical
TSKB0047 benchmark fairness protocol.
