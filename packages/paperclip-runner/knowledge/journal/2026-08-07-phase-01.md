# Context

Phase 1 makes the language-neutral runner contract executable before networking
or a real harness exists. The checkpoint must validate a scripted PRP fixture,
reduce ordered events deterministically, and show the same snapshot in a CLI and
standalone browser without importing Paperclip core.

# Decisions

1. Keep JSON Schema under `protocol/schemas/` as the language-neutral source of
   truth. Generate checked TypeScript schema constants and derive public types
   with `json-schema-to-ts`.
2. Accept unknown optional object properties for forward compatibility while
   failing closed on unknown required protocol, fixture, event, schema, enum, or
   required-field semantics.
3. Treat scripted fixtures as bound records: all run/session identities agree,
   controller commands are contiguous, duplicate event IDs are byte-equivalent,
   and the single proposed result matches the declared fixture result.
4. Keep the reducer pure and I/O-free. It deduplicates before projection,
   records source gaps/out-of-order delivery, never invents events, and returns
   an unchanged snapshot when an applied batch is replayed.
5. Import one `replayPhase1FixtureText` path from both CLI and browser so static
   replay cannot develop two validation or projection contracts.
6. Use source-compatible shadcn Button, Badge, Card, and Textarea wrappers in the
   standalone Vite page. Component files contain no visual literals; semantic
   values live in the page's local CSS token layer.
7. Keep Rust at the production boundary by validating required versions and
   fixture bindings, then comparing its parity summaries against the same
   checked golden corpus.
8. Target current evergreen browsers in Vite. Ajv remains in the Phase 1
   devtool bundle so the browser validates the authoritative schemas directly.

# Failures and corrections

- The first browser build used Vite's default legacy target. The installed
  esbuild cannot downlevel Ajv's runtime code to that target, producing 249
  transform errors. The devtool now declares `target: "esnext"`, matching its
  current-evergreen-browser scope; the production build passes.
- The Playwright web-server command included a literal `--`, so Vite ignored the
  requested port and attempted its default. The command now invokes
  `pnpm exec vite preview` with explicit arguments.
- The first browser assertions used broad accessible-label/text selectors that
  correctly matched more than one element. The tests now use an exact fixture
  label and a scoped result-summary test ID. Both browser cases pass.
- The execution image had neither Cargo nor Chromium's optional Linux shared
  libraries. A verified official stable Rust toolchain and extracted Ubuntu
  browser libraries were placed only in the run scratch directory. No system or
  repository runtime state was changed.
- The repository-wide token gate currently reports 12 existing onboarding color
  literals outside this package. The new package-local browser token gate passes
  and no `ui/` files were changed.

# Known gaps

- Static fixtures only: no runner daemon, network transport, durable outbox,
  ACK, reconnect, or live browser subscription.
- No fake or real harness process and no control-plane persistence or authority.
- The browser is a first useful replay inspector, not the later full reference
  console; it has no composer, live controls, request resolution, or dark theme.
- The unminified validation path keeps Ajv in the browser bundle. Bundle
  optimization is deferred until behavior and schema boundaries are stable.
- Linux browser automation still requires the normal Playwright host libraries;
  the tutorial names the standard installation command.
