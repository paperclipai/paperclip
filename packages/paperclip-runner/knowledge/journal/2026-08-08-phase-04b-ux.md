# Context

Phase 4b builds a live browser console over the Phase 4 Codex driver. Before
UI implementation, the UX gate (PAP-16832) had to approve the interaction map
for every §29.1 surface and record reuse/adapt/reject decisions for
source-adapted shadcn/ui and Vercel AI Elements primitives.

# Decisions

1. Extend the existing `devtools/browser/` app and its token layer with a new
   Live console mode. Do not build a second shell or restyle frozen Phase 1–3
   surfaces.
2. The reducer/canonical event stream is the only UI data contract. Adapted
   third-party components are re-typed against `SessionSnapshot` shapes;
   AI SDK message/part types are banned as protocol authority.
3. Zero new runtime dependencies. Adapt five AI Elements shapes
   (Conversation, Message, PromptInput, Reasoning, Tool) and six shadcn
   patterns (Tabs, menu-button subset, Dialog on native `<dialog>`, Tooltip,
   Alert, Separator/Kbd as CSS) in the established `ui-*` token idiom.
   Reject markdown/highlighting/palette deps for the tracer; several are
   named Phase 5 candidates.
4. Steering resolves through an explicit pending → acknowledged /
   stale-rejected chip; rejected text is recoverable via "Send as new
   message". The three interrupt races get distinct preserved terminal
   states; the session is never replaced.
5. Request cards render only upstream-offered actions and resolve only on
   `runtime_request.resolved` (UI-level single-response guarantee).
6. Goal and child-steering capability gaps render disabled controls carrying
   the exact upstream diagnostic — never hidden, never emulated.
7. Keyboard and accessibility acceptance criteria (K1–K9, A1–A7, V1–V5) are
   the testable bar for the spec's component/keyboard/accessibility checks.
8. Four token additions (accent pair, raised surface, medium motion,
   z-scale) are a recorded system change, not inline values.

# Failures

- The first mobile render wrapped the header brand line character-by-character
  and clipped the inspector toggle; fixed by stacking the header and hiding
  desktop-only controls below the 64rem breakpoint before approval.

# Gaps and next questions

- Exact upstream diagnostics for goal/child-steering gaps depend on the
  PAP-16833 fixture work; the map requires verbatim pass-through, so no UI
  copy is blocked on them.
- Markdown rendering and syntax highlighting are deliberately deferred; the
  Phase 5 SDK console should revisit `Response`, `CodeBlock`, and `Context`
  with a dependency decision at SDK scope.
