# Context

Phase 3 proves network recovery before a real model driver or production control-plane connection exists.

# Decisions

1. Use a real loopback WebSocket. Keep the mock core and all state inside the package.
2. Use a one-time bootstrap ticket. Exchange it for a connection lease on the first connection.
3. Write events before network delivery. Remove events only after a cumulative acknowledgement.
4. Keep event IDs and command IDs stable across reconnect and restart.
5. Store processed command IDs with the outbox. Repeated commands do not repeat effects.
6. Protect P0 events when the outbox reaches its limit.
7. Use a private atomic JSON state file for the tracer. Do not store the bootstrap ticket.
8. Show counters and states in diagnostics. Do not show authentication secrets.
9. Resolve and pin only loopback destinations before sending a bearer
   capability. Reject ambiguous or mixed DNS answers.
10. Use exclusive random temporary state files, no-follow opens, ownership and
    mode checks, atomic rename, file sync, and directory sync.
11. Capture and remove the bootstrap environment value at daemon entry. Keep
    bootstrap and lease values in overwrite-on-drop buffers.

# Failures

- The first lost-ACK path let a socket write error escape before reconnect. The
  recovery loop now records the failure, preserves state, and reconnects.
- The security diagnostic first reported capability persistence with fixed
  `false` values. It now derives both facts from the runner state file and the
  tests assert the result.
- The normal browser run could not start Chromium because this minimal host did
  not include `libatk`. The supported rootless verifier downloaded private
  runtime libraries and all seven browser checks passed.
- Documentation validation found the recovery screenshot link before the file
  was captured. The browser proof produced the screenshot, it was inspected,
  and the final documentation check passed.

# Known gaps

- The runner transport and durable store are Rust. The mock core, fault driver,
  evidence recorder, and browser peer are TypeScript.
- The WebSocket uses loopback `ws` for local proof. Production `wss`
  certificate and proxy policy remain deferred.
- The mock core supports one runner session.
- The atomic JSON state is a tracer store. A production database format,
  migration policy, and long-term processed-command retention remain deferred.
- Lease replacement after expiry is an external fresh-bootstrap action. This
  phase does not implement a production lease-renewal service.
