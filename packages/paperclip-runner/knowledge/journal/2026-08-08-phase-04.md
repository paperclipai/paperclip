# Context

Phase 4 connects the already deterministic mock core and reducer to a real
Codex app-server process. It proves the driver boundary without adding a
Paperclip production integration or browser surface.

# Decisions

1. Use app-server v2 JSON-RPC over local stdio. Keep its experimental network
   transport out of the runner WAN contract.
2. Keep runner, normalized session, driver thread, provider session, turn,
   item, and source-event identities separate and stable.
3. Resume only the exact persisted thread. Never replace a lost session with a
   new one.
4. Use one compact `paperclip.skillless_task.v1` text envelope. Disable
   automatic skill, app, collaboration, plugin, memory, and multi-agent
   instruction blocks in thread config.
5. Pass an allowlisted child environment. Record key names, never values.
6. Register separate `paperclip_finish` and `paperclip_block` dynamic tools.
   Normalize both into the same canonical result validator.
7. Commit the first valid semantic result. Treat the same later result as an
   idempotent retry and reject any changed result.
8. Use app-server capabilities to implement or explicitly degrade read, steer,
   interrupt, usage, structured output, dynamic tools, and reconciliation.
9. Normalize every provider notification through the existing PRP validator,
   reducer, and replay path.
10. Keep the real example safe: requested workspace-write sandbox, no network
    request, one allowed file, and exact output verification. Treat returned
    provider sandbox facts as authoritative when they add managed state roots.
11. Prove credential-file and unrelated-secret isolation directly. Do not use
    whole Codex-home unreadability as a proxy in warmed environments.

# Failures

- The first real structured-output request failed because the schema combined
  `const` with no explicit JSON type. Adding `type: "string"` fixed the
  app-server validation error; focused tests now assert the exact schema.
- A sandboxed app-server could read but not update the signed-in Codex SQLite
  state. Real-session verification therefore runs with normal local Codex
  access, while all deterministic driver tests use the in-process fake
  transport.
- An unrelated broken skill was present in the host Codex home. Thread config
  now disables automatic skill instructions, and the context assertion checks
  both the policy flags and empty instruction-source list.
- The first redaction test stopped reading before the diagnostic event. It now
  consumes the complete deterministic event sequence before asserting that the
  secret is absent.
- The original authenticated proof denied the entire Codex home. Codex 0.132.0
  materializes and injects `~/.codex/memories` as a writable legacy root, so the
  parent directory becomes readable after warm-up even though `auth.json` and
  `config.toml` remain protected. The recorder now probes those files directly.
- A non-`done` semantic result could reach unconditional `hello.txt` and
  `isolation-ok.txt` reads. The recorder now stops on the result diagnostic and
  reports any missing accepted-result file by name.

# Known gaps

- The reference driver is TypeScript while the production runner direction is
  Rust. It proves the contract and real provider mapping, not the final daemon
  implementation language.
- Real-model choices are nondeterministic. The focused fake-transport suite is
  the conformance authority; the recorded real trace is a hands-on proof.
- The Codex permission profile is a requested policy, not stronger evidence
  than the returned sandbox. Current Codex versions may expose provider-managed
  state roots such as `~/.codex/memories`; Phase 4 guarantees credential-file
  isolation rather than whole Codex-home directory isolation.
- The safe task may use a command instead of a file-change item. Deterministic
  tests cover both file and request mappings.
- This package proof does not supply production MCP bindings, approval UI,
  multi-tenant credentials, or control-plane status authority.
