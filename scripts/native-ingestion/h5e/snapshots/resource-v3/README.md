## PostgreSQL startup boundary and supervision

A tiny explicit **server-only** preload verifies the entire current compiled
`server/dist/index.js` against the actual inventory and requires one existing
`const runningPid = getRunningPid();` anchor. It inserts one awaited prestart
callback immediately before that normal embedded reuse check. The installed
file stays unchanged; the original reuse branch and subsequent application
startup remain. The hook runs before all measured epochs. It does not patch
spawn, move an existing postmaster, add a PID gate, or affect a hot append path.

This point is intentional: the frozen remote assembly has already supplied TLS/
Runner variables and normal startServer has applied secrets-path environment.
A separate shell prestart would have missed those ordinary PG environment fields.
The callback uses the actual server's home/config/data directory, requires an
empty fresh cluster, resolves the normal installed embedded-postgres18.1.0-beta.16
and native Linux artifacts with exact hashes, and uses normal `detect-port`
selection. It initializes with user/password paperclip, auth=password,
`--encoding=UTF8 --locale=C --lc-messages=C`, including the normal constructor's
additional `--lc-messages=C`. Only the setup password-file location changes; it
is private and is removed in finally. No expected provider events are seeded.

The direct PG command is the normal executable with `-D DATA -p SELECTED_PORT`
and the actual ordinary environment plus LC_MESSAGES=C. Environment values go
through a private0600 file, never argv, receipts or logs; line/NUL-containing
values fail instead of changing quoting. Actual process environment is compared
by a digest, never by an assertion that prints values. The private file is removed
only after PG retirement. Do not archive it or any owned server home/master key.

The privileged operation creates exactly one fresh root-owned transient systemd
service, Type=exec, User/Group=ubuntu, Delegate=no, NoNewPrivileges=yes,
ProtectControlGroups=yes and empty effective/bounding capabilities. The child
cannot directly migrate through root-owned non-writable cgroup control files;
the actual PID status and read-only cgroup mount are verified. No numeric CPU,
memory, IO or cpuset limit is set. Actual leaf and parent control values must
match the separately frozen accounting qualification. Missing controller files
are explicitly null, never enabled or guessed. RuntimeMax=30m, Restart=no and
SIGINT/control-group shutdown with30s timeout are verified from actual unit
properties. This is accounting containment for the controlled PG fixture, not
a claim of a general hostile-code sandbox.

A small source-bound ExecStopPost writer runs only after the measured epochs.
While that command keeps the unit loaded, it reads systemd's own-unit
ExecMainPID/InvocationID/exit status plus SERVICE_RESULT/EXIT_CODE/EXIT_STATUS and
atomically retains a private receipt bound to the ready identity/release/source.
Its Node command clears NODE_OPTIONS only for this shutdown writer, keeping
application fixture loaders out of that path. PG's ordinary argv/environment
remain unchanged. The writer performs no application/database work. Live Linux
qualification must verify the actual installed systemd property/env behavior.

Systemd places its direct ExecStart PID into the unit before exec/fork. After
readiness, MainPID must equal the owned postmaster.pid, actual PG executable,
birth, unit invocation, expected user and exact cgroup inode/path. A preexisting
unit/path, fallback postmaster, replacement, parent/data/port/source mismatch or
permission failure invalidates the capture. The first serving qualification must
verify the actual installed systemd supports these properties and environment
semantics; source tests are not such evidence.

This changes PG startup/shutdown supervision and security context for diagnostics.
It must be disclosed and identical for compared B0/B1/final resource runs. The
normal server follows its supported existing-cluster branch; the private
controller owns PG shutdown after normal app teardown. Latency acceptance and
recovery checks continue using ordinary server-owned PG startup. Dedicated unit
topology can affect scheduling even with equal numerical controls; diagnostic
timings do not replace unprofiled acceptance.

## Capture lifecycle and measurement windows

The wrapper imports the unchanged normal Playwright config, preserves its
bootstrap/fixture/composer-loader environment and owning journey, then adds only
beforeAll/afterAll hooks. It resolves the actual server counter metadata/config,
never the worker's newly generated home. Before the first owning emission it
requires the emitted normal reuse log, actual unit proof, exact same SQL cluster
and initial proc/PG observer samples. Observers and controller stay outside PG's
cgroup. The SQL observer's backend is inside and its database CPU is included.

External-v2 binds the actual SQL backend PID/birth/direct parent/executable,
boot, PID/network namespaces, owned config/data directory, actual selected port
and dedicated cgroup to that postmaster before/after every sampled SELECT.
Only explicit local127.0.0.1 TCP is accepted; URL/credentials stay in memory.
Driver/environment fallback cannot select another cluster. The preferred port
and actual normally selected port are separate frozen facts. Changed source or
live ownership fails the capture. Its proc CPU remains an observed lower bound;
unregistered provider children stay unclassified. No full Runner/provider CPU
claim or Rust Vec/state-save/syscall metric is added.

After the owning test returns, the hook requires an outer sample later than the
hook entry, stops both collectors, verifies their exit/complete raw-hash receipts,
and records a final live PG aggregate **before normal app teardown**. It then
uses only finite loopback Runtime.evaluate to finalize the six Node hooks and
independently rereads receipt/log/observer hashes and zero pending buffers/scopes.
No Profiler API or V8 CPU sampling is used. Missing hooks, errors, overflow,
stale/foreign receipts or observer failures fail rather than becoming zero work.

The unchanged owning report and exact attachment must pass once without retry;
independent source clocks/payload/identity checks, durable callbacks, results,
normal final drainage, leases and reload remain mandatory. Marker joins retain
the existing Stop durable-prefix/raw-tail policy; ordinary wire ACK is not a
universal database durability promise. An observer flush alone does not prove
the workload completed. No failure or original deadline miss is regraded.

For non-Stop cases, terminal `[epochMs,settledAtMs]` and later fully verified
`[epochMs,h5.independentDrain.verifiedAtMs]` stay separate. Server Node CPU,
query-build attempts and acknowledged **outer** COMMITs use their own numerical
brackets. PG cluster CPU uses the unchanged cgroup bracket helper, includes
maintenance and SQL-observer work, and retains all read spans and scope proofs.
Each numerator independently needs at least six interior samples and at most10%
boundary uncertainty. Ratios use the exact independently matched durable text
delta count, not all normalized events or successful transactions guessed from
BEGIN. Short windows and Stop supply no ratios. FULL requires both loaded
burst512 windows to qualify for all CPU/SQL/TX numerators; otherwise raw data
remains and the resource gate fails. SMALL never supplies ratios.

The fully verified rate includes oracle/reload/lease/screenshot work, not the exact
last commit instant. Node RSS/queue and event-loop values are sampled observations;
no instantaneous memory peak or p99 is inferred. PG memory.current/peak are scope
charges/lifetime values; proc RSS sums double-count shared pages. Lock polls are
occupancy evidence, not exact waits/holds. Database returned rows/stat counters
are not rows examined: retain the separate qualified source EXPLAIN plans.
Observer read/encode/flush CPU and SQL work remain disclosed. Actual raw samples,
failures, retries, timeouts, complete drainage and resource tradeoffs must survive
